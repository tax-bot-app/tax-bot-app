# さじかげん｜確定仕様

## リクエスト制御

- Next.jsのリクエスト前処理は、ルート直下の `proxy.ts` で行う。
- `MAINTENANCE_MODE=off|soft|hard`、Supabase SSRのセッション同期、Cookie引継ぎ、allowlist、matcherの挙動は従来どおり維持する。
- Next.js 16で非推奨の `middleware.ts` は使用しない。

## トップページUI

- 上質な士業サイトを基調とし、アイボリー、深いネイビー、控えめなゴールドで統一する。
- 黒背景・ダークテーマは使用しない。
- PCのファーストビューは、価値訴求と無料体験を左右に配置する。
- スマートフォンは、価値訴求、信頼情報、無料体験の順に1列で表示する。
- 既存の無料体験、相談例、回答後CTA、プラン導線の機能は維持する。

## フォント配信

- Geist、Geist Mono、Yuji Syukuはnpm依存から同梱し、ビルド時にGoogle Fontsへ接続しない。
- 既存のフォントファミリーと表示箇所は維持する。
- Stripeの秘密ENVはAPIリクエスト処理時に検証し、モジュール読込時には参照しない。

## 有料プラン

| プラン | 月額（税込） | 月間利用回数 |
| --- | ---: | ---: |
| Lite | 1,480円 | 5回 |
| Standard | 4,800円 | 30回 |
| Enterprise | 9,800円 | 100回 |

- 登録直後の `free` は有料チャットを利用できず、月間利用回数は0回とする。
- `free / Lite / Standard / Enterprise` の月間利用回数は `app/lib1/planMaster.ts` を唯一の定義元とし、チャット・管理API・Webhookで共用する。
- 新規Checkoutは `PRICE_ID_LITE_NEXT`、`PRICE_ID_STANDARD_NEXT`、`PRICE_ID_ENTERPRISE_NEXT` を使用する。
- Webhookは切替前後のPrice IDをいずれも正しいプランへ判定する。

## Stripe Webhook

- Webhookイベントは `processing`、`processed`、`failed` の状態で管理し、正常完了時だけ `processed` とする。
- 途中で処理に失敗したイベントは、Stripeからの再送時に再実行できること。
- 同一イベントの同時処理を避け、一定時間停止した `processing` は再取得できること。
- 複数の有効な契約がある場合は、認識できるPrice IDのうち最上位プランを適用する。
- 有効な契約が存在するのにPrice IDを1件も認識できない場合は、`free` へ変更せず処理を失敗させ、再送対象とする。
- 現行・旧Price ID、複数契約、未知Price ID、解約済み契約のプラン判定は自動テストで固定する。

## Stripe Checkout

- Checkout完了・キャンセル後の遷移先は、リクエストの `Origin` を使用せず、`NEXT_PUBLIC_SITE_URL` のオリジンへ固定する。
- 本番環境の `NEXT_PUBLIC_SITE_URL` はHTTPSの絶対URLとする。
- 認証callbackとCustomer Portalの戻り先も同じ検証済みオリジンへ固定し、受信リクエストの `Origin` や別のURL用ENVには依存しない。
- 新規Checkout Session作成には、利用者・プラン・Price IDから生成した冪等キーを付与する。
- 同じ条件の同時リクエストや再送は同じCheckout Sessionへ収束させ、二重契約の入口を作らない。
- 冪等キーには利用者IDを平文で含めず、ハッシュ化する。

## ブラウザ向けセキュリティヘッダ

- 全ルートへクリックジャッキング、MIME誤判定、過剰な参照元送信を抑止する共通ヘッダを付与する。
- カメラ、マイク、位置情報、ブラウザの決済機能は当サイトへ許可しない。
- 本番環境だけHSTSを付与し、ローカル開発のHTTP接続には付与しない。
- Meta Pixel、Supabase、Stripe等の既存通信を止める全面的なContent Security Policyは、許可先を実地確認してから別工程で導入する。

## 有料チャットの回数制御

- AI回答の生成前に当月利用数を確認し、月間上限到達済みの場合は回答生成を開始しない。
- AI回答が正常に生成された後の正式な回数消費と同時実行時の最終判定は、既存の `consume_talk_v2` で行う。
- 無制限対象ユーザーは生成前の上限判定から除外する。
- 利用数の事前確認に失敗した場合は、AI回答を生成せずエラーとする。
- 上限到達、無制限、利用数確認失敗の分岐は自動テストで固定する。

## 無料体験

- 登録不要の無料体験は1端末につき3回までとする。
- Cookie、localStorage、端末識別子の3層で使用回数を制限する。
- 旧仕様で既に1回使った端末は、その履歴を1回目として引き継ぎ、残り2回とする。
- 4回目以降は回答生成せず、プラン確認へ案内する。
- 回答生成のタイムアウト、例外、空回答では、そのリクエストが確保した端末枠を解放し、無料体験回数を消費しない。
- ガードレールで遮断した相談は、抜け道防止のため従来どおり1回消費する。
- 正常回答、空回答、タイムアウト、例外時の端末枠処理は自動テストで固定する。
- 無料体験の直後に、出張日当2万円を題材とした相談例・回答例を常時表示する。
- 回答例は可能性だけで断定せず、金額の妥当性、役員・従業員間のバランス、出張実態、旅費規程等の確認が必要であることを示す。
- 回答例のCTA「自社の場合を相談してみる」から無料体験の入力欄へ戻し、入力欄へフォーカスする。
- 無料体験の直前に、野口税理士の顔写真、資格・肩書き、法人税務・税務調査対応の実務経験を簡潔に表示する。
- 無料回答の箇条書きが途中で改行されても、続きの文を同じ項目として結合し、不完全な文のまま表示しない。
- 無料回答は「要点2件・注意1件」に固定せず、成立条件が伝わる範囲で要点最大4件・注意最大2件を表示する。
- デモ回答の表示上限は1,200文字とする。上限を超える場合は会社別の確認質問を先に確保し、本文側を直前の完結した文で調整する。
- 金額相談では提示額に正面から反応し、有利に整理できる可能性、成立させるための主要条件、税務調査上の注意点まで無料回答で示す。根拠なく肯定したり、未提示の数値レンジを創作したりしない。
- 無料回答の最後には、会社規模、金額、対象者、頻度、規程、証拠、現在の運用等から、結論が動く会社別の確認質問を1〜3行必ず表示する。
- 無料回答が正常に表示された直後に、その相談について有料版で具体化できる内容を表示する。
- 有料版の具体化内容は、会社の金額・運用条件に沿った線引き、必要書類、税務調査での想定質問と説明方法、顧問税理士への質問文とする。
- 回答後CTAは「この相談の続きを整理する」とし、プラン選択を開く。

## 新規登録後の申込導線

- プラン指定なしで新規登録した場合、メール認証後はチャットではなく、ログイン済み状態でプラン選択へ遷移する。
- 未契約のfreeユーザーがチャットを直接開いた場合は、入力・送信を無効にしてプラン選択を自動表示する。
- 未契約状態でチャットAPIが拒否した場合は、英語のエラーを表示せず、プラン選択を案内する。

## OpenAIモデル継続運用

- 最優先は、モデルの提供終了による回答機能停止を避けること。
- 通常時は用途別の指定モデルを使う。
- 指定モデルが提供終了・存在しない・利用権限がない場合に限り、設定済み候補へ自動で切り替えて同じ処理を再試行する。
- 認証エラー、レート制限、入力不備、OpenAI全体障害はモデル切替の対象にしない。
- 切替は承認待ちにせず即時実行し、Vercelログへモデル名と用途を残す。質問本文、回答、APIキーはログへ出さない。
- 候補の優先順は用途別ENV、共通ENV、コード内の緊急候補とする。
- 明示候補がすべて使えない時だけ、APIで現在利用できるモデル一覧を取得し、一般向けGPTの厳格な名前規則に合う新しい候補から疎通確認する。
- snapshot、Codex、画像・音声等の用途違いモデルは自動選択しない。
- OpenAIの提供終了告知とメールも定期確認し、後継モデルをENV候補の先頭へ追加する。自動選択は更新忘れ時の最後の保険とする。
